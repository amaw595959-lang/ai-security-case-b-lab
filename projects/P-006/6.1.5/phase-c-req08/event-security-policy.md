# Phase C scoped event policy

The lab invokes the pinned native new-chat handler through a separate, authenticated notice route with only the frozen T04 synthetic input and the approved loopback model. A trusted test operator binds the verified standard account ID in private temporary state. The route attaches a server-side context after checking that identity. The context binds to the chat ID reported by the native saved-chat producer. Client parameters, model output and email text confer no notice authority. Ordinary routes use their existing policy. [Defect analysis](defect-analysis.md) · [T04 fixture and oracle](../../6.1.1/case-b-test-design.md#p006-611-t04--proposed-req-08-storage-event-and-log-handling)

| Event class | Decision and permitted recipients | Observable behavior |
| --- | --- | --- |
| Notices · `chat.created`, `message.created` and `chat.finished` | For the bound actor and chat, write fixed metadata to the private lab operator journal. Treat all original content and native actor and resource identifiers as restricted. The direct completion-to-inbox edge is closed for this notice request. | Each allowed delivery has an attempt ID and sequence. No notice envelope or body is sent to the native operational sinks or inbox. The authorized private response and SQLite content follow the original access policy. |
| Unrelated application events | The upstream publisher delivers the original event through its applicable native sink policy. The assessment runs in a loopback-only namespace with functions and outward destinations disabled. | Positive native sink observations prove that the original call occurs. No notice journal record is created for the unrelated event. |
| Security and audit events | Unrelated role and access events retain the original identity and native sink behavior. Preserve native `METADATA` auditing, including authentication. The notice route records its own body-free HTTP decision. Scoped `chat.failed` and `model.provider_request.failed` write metadata to the private journal as failure records. | A role-update event can reach the native session sink. A notice denial has a safe reason and correlated HTTP status even when the request never reached publication. A failure receipt includes its known type, without error text. |
| Restricted content | Keep original envelopes, previews, titles, candidate text, credentials and native identities out of scoped operational delivery. Never dispatch an unprojected governed event to a different sink if projection or delivery fails. | The independent sink accepts only the fixed schema. Denied or failed deliveries write a bounded reason to a separate decision journal. A journal failure has a body-free console fallback. |
| Unsupported type, malformed envelope or incorrect bindings | Deny within a governed notice operation. Use the upstream catalog and behavior when the notice policy does not apply. | The decision record reports a fixed reason without repeating unknown names, inputs or exception messages. A duplicate event ID in the same admitted request is recorded and does not repeat the projected delivery. |

The notice operator journals permit only the run and attempt UUIDs, per-attempt event sequence, known event name, fixed actor and resource aliases, fixed action, outcome, fixed reason and policy version. The HTTP decision includes only the attempt, outcome and numeric status alongside fixed metadata. The operator reads these files through a private temporary directory with mode `0700` and journal files with mode `0600`. The native audit file is a distinct private store for approved body-free operational metadata. It may include upstream account metadata from other lab routes. No external collectors or real credentials are configured.

The correction uses a source patch against the pinned publisher and the direct inbox call. A failure at the scoped metadata consumer cannot re-enter native fan-out. Unrelated dispatch continues to isolate errors per native sink and preserve the envelope and ordering specified by upstream. The native publisher and inbox functions keep their identities. The scope follows the one admitted request and its new saved chat. The isolated request uses non-streaming inference and does not authorize further edits, sharing, delegated actions or other routes with the restricted fixture.

The application schedules the 12-second lab expiry after completion of the admitted request, for the bound chat and owner. An independent reader can verify both authorized access before expiry and denial after logical deletion. Process recovery, durable delivery and deduplication, other producers or deployments, provider failure diagnostics, backups, rotation and physical remnants remain outside this retest.

The scope addresses `P006-611-REQ-08` and `P006-611-REQ-09` and the corresponding `P006-611-INV-06` and `P006-611-INV-07`. Storage, event, logging and excluded effect checks use existing boundaries 2 and 6–8. A B-05 private reply and the effects of that reply are separate claims. This retest exercises data containment under T04. The original model-behavior assessments retain their recorded outcomes. ## Acceptance

1. Match upstream file hashes to the image before applying the patch and retain the patch as a review artifact.
2. Confirm allowed scoped deliveries of each expected type and sequence. Independently read the native observer and the notice journals, including positive controls at both destinations.
3. Verify that malformed or unsupported input, a wrong binding, a duplicate event and a failed consumer yield their declared decisions without content or a native fallback.
4. Confirm ordinary unrelated and role-update delivery through the native chain and inspect the separate role and chat database effects.
5. Match the HTTP decisions, private reader checks, stored input fixture and logically deleted rows. A missing positive control or an unobserved destination leaves the corresponding claim inconclusive.
