## Before-change source findings

| Boundary | Pinned Open WebUI behavior | Effect of the original overlay |
| --- | --- | --- |
| Native producers and event builder | The saved-chat create path writes private state, then publishes `chat.created`, the initial `message.created` with a preview, and the assistant-placeholder event. `build_event` validates the name, assigns identity and timing, and sanitizes by property name and length. It can preserve restricted text in ordinary fields. [Create producer][create] · [Event builder][build] | The global builder wrapper projects two event types based on request path and account email. It removes the message and subject before delivery and sets request state used by the audit writer. It starts expiry as a side effect of building a completion. The builder still returns ordinary events for other paths. [Original implementation][old] |
| Publisher and delivery | `publish_event` accepts a definition or existing envelope and awaits the native dispatcher. `_dispatch_event` iterates socket, function, webhook and notification sinks. It catches each sink's exception and continues with the next sink. [Native dispatch][dispatch] | Both experimental modes replace `_dispatch_event`. Only the selected route and two types write to the comparison or controlled journal. The native chain is bypassed for **every** event. Ordinary `chat.created`, event functions and webhooks outside the experiment, and internal security effects can silently disappear. [Original implementation][old] |
| Security-critical effects | `SocketSessionEventSink` refreshes access for covered chat/folder changes and disconnects sessions for `user.role_updated` and `user.deleted` using the original subject ID. The administrator user-update handler can publish the role event. [Socket sink][socket] · [Role-update producer][role] | The dispatcher replacement skips the socket sink along with the external sinks. A successful application operation or archive receipt alone cannot show that its session effect ran. This is a defect of the experimental overlay. |
| Direct inbox | `publish_chat_finished_event` builds an envelope, calls `consume_event` inside a database transaction, emits changes to recipients, then publishes via the dispatcher. The chat inbox consumer can read the saved assistant message, find mentions and create eligible notifications. The same consumer handles other event types. [Completion producer][completion] · [Inbox consumer][inbox] · [Recipient check][recipients] | Controlled mode replaces `consume_event` for all callers with an empty result. Event projection alone would be insufficient here because the direct consumer can read a separate content copy. A request-specific guard is needed at this producer. |
| HTTP audit and diagnostics | Native middleware handles auth endpoints separately from ordinary path filters. `METADATA` uses no request/response body capture. The request and response levels can record text that key-based redaction cannot classify. Diagnostic paths are separate. [Audit registration][audit-register] · [Body capture][audit-body] · [Audit filters and fields][audit-fields] | Controlled mode disables native HTTP audit, then logs a decision only if an eligible event has already marked the request. Pre-publication failures can have no assessed receipt, and native authentication auditing is disabled with it. The old comparison deliberately enables body capture. No such body capture is needed after the correction. |
| Private data and retention | Authorized private chat and model processing have a separate access policy. Native dispatch and inbox receive identifiers that do not grant permission to persist a telemetry copy. | The old builder schedules a short, owner-checked deletion on completion. Malformed IDs or another builder call can affect scheduling. The corrected experiment should bind expiry to the approved operation and keep its outcome separate from delivery. |

## Baseline and fix decision

Before implementation, replay the archived ledgers and check their manifest. Then compare the re-executed old workflow and a positive native dispatch observer with the old dispatcher installed. For the dispatch regression, require unrelated and role-update events to reach an independent native sink and require the native role sink to call the tested session-disconnection boundary. Test failed sinks with positive downstream delivery. An absent destination with no positive control is inconclusive.

Use an explicit server-admitted synthetic notice operation. Apply a small source patch to the pinned publisher and the direct completion-to-inbox edge, with native behavior when the request carries no approved notice context. Project governed content to a private journal or produce a bounded rejection. Keep required notice failure records observable and leave unrelated security and audit handling on its established path. Preserve the archived experiment as separate evidence.
